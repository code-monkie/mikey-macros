How it works

Lifecycle

  1. Out of the box: a new character starts on the Default collection with auto mode on. Each class spell it learns gets a macro: the collection's if it has one, otherwise Default's, otherwise a generated one (see Which macro a spell gets). At level 1 the starting spells on the bar become their macros in place; later, the macro window opens so you can drag new ones on.
  2. With a collection (opt-in): /mm use <name>; its macros appear as you learn their spells. /mm sync creates them for spells you already know, and /mm sync all creates the whole class list at once, so you can lay out your bars once.
  3. Trimming: each macro is written with only the spells the character knows (see trimming rules). Fall-through lines and #showtooltip icons therefore always work, and a macro with nothing known yet shows a question mark.
  4. Automatic updates: when you learn a spell or change your main-hand weapon, the collection macros (Default's included) are rewritten. Changes are batched (half a second) and wait for combat to end.
  5. Rewriting edits a macro in place, so it keeps its place on your bars.

The addon owns its macros

Collection macros, Default's included, belong to the addon: an edit made in the in-game macro window is overwritten the next time the macro is rewritten. Make permanent changes in the collection's class file (see the Collections guide). Renaming a macro in game takes it out of the addon's hands. Generated macros are the other way round: they're written once and never touched again, so edit them freely. General (account) macros are never touched.

Spell detection

The addon reads the spellbook, by name, for spells that are actually learned (not future or off-spec spells). It uses retail's C_SpellBook API where present and the Classic spellbook API otherwise, so the same files work on Classic Era, WoW: Forever and retail. A generated macro's shape comes from the spell's own data: harmful or helpful, its range, and its description (toggles, pet-only spells). On Classic clients the range is read with GetSpellInfo, because their C_Spell.GetSpellInfo reports the minimum and maximum range the wrong way round.

Saved data

Per character (MikeyMacrosCharDB): the collection chosen with /mm use, whether auto mode is on, and the names of the class spells auto mode has already seen. The macro lists live in the addon's files; the macros themselves live in the game's own macro storage.

Performance

A few kilobytes of data, no OnUpdate, no timers. Work happens only when spells or the main-hand weapon change: one spellbook scan and a string comparison per macro.

Limits

  • Character macros: 30 per character on Classic Era and retail. WoW: Forever is likely the same but not confirmed yet (/dump MAX_CHARACTER_MACROS). /mm sync reports anything that didn't fit.
  • 255 characters per macro body, 16 per name.
  • Macros can't be created or changed in combat.

Troubleshooting

  • A key shows "?": you don't know any of its spells yet. Expected.
  • A spell got no macro: check chat. no macro (excluded) means it's on the class's exclude list; no free character slots means you're full. A leveled character the addon saw for the first time gets nothing until /mm sync.
  • A character follows a collection you didn't pick: it already had that collection's macros (they're stored on Blizzard's servers, so they survive a cleared WTF folder), and the addon kept it following them. /mm use default changes that.
  • A conflict: line at login: a spell is both excluded and in a macro this character follows. Take it off the exclude list or out of the macro.
  • A macro didn't update after training: /mm update. If it still doesn't, check the spell's name in spells matches the spellbook exactly.
  • A new class file isn't picked up: it must be listed in mikey-macros.toc, and a new file needs a full game restart.
  • A hand-made macro disappeared on /mm clear: its name matched a collection macro; see name collisions.
  • Lua errors: install BugGrabber and BugSack and check what they caught.
