Collections guide

How to edit an existing collection, start a new one, and manage which collection each character follows.

For the macro format itself (fields, trimming, conventions), see Writing macros.

What a collection is

A collection is one person's macro lists: a folder under Collections/ named for its owner, with one file per class they cover.

Collections/
  Mikey/   Rogue.lua  Shaman.lua  Hunter.lua  Druid.lua
  Ulako/   Shaman.lua  Mage.lua

Each file adds one class to its owner's collection:

local _, ns = ...

ns.Collection("Mikey").ROGUE = {
    { name = "SS", spells = { "Sinister Strike" }, body = [[
        #showtooltip
        /startattack
        /use Sinister Strike
    ]] },
    -- more macros ...
}
  • The string in ns.Collection("...") is the collection's name. It should match the folder name (a Lua file can't see which folder it's in, so the name has to be written out).
  • The key after it (ROGUE) is the game's class token: WARRIOR, PALADIN, HUNTER, ROGUE, PRIEST, SHAMAN, MAGE, WARLOCK, DRUID (retail also DEATHKNIGHT, MONK, DEMONHUNTER, EVOKER).
  • A collection doesn't need every class, only the ones its owner plays.
  • Every collection file must be listed in mikey-macros.toc, after Core.lua.

Which collection a character follows

Each character follows exactly one collection for its class, picked in this order:

  1. the collection chosen on that character with /mm use <name>, if it has the character's class;
  2. otherwise Mikey's, if it has the class;
  3. otherwise the first collection, alphabetically, that has the class;
  4. otherwise none: the class isn't supported yet, and /mm says so.

The choice from /mm use is saved per character (MikeyMacrosCharDB in the character's SavedVariables). /mm collections lists every collection and the classes it covers, and marks the one the current character follows; /mm list starts with it too.

Examples with the collections above:

Character Follows Why
Rogue Mikey only Mikey has a rogue list
Mage Ulako no Mikey mage; Ulako is the only one
Shaman Mikey both have one; Mikey is the default
Shaman after /mm use ulako Ulako chosen on that character
Priest nobody no collection has a priest list

Editing an existing collection

All edits happen in the collection's class files, in any text editor. The addon reads them at load, so after saving:

  • changed an existing file: /reload in game;
  • added a new file: add it to mikey-macros.toc and restart the game (a new file isn't picked up by /reload).

Change a macro

  1. Edit the macro's body (or spells) in Collections/<Owner>/<Class>.lua.
  2. /reload. Characters following that collection update within a second. /mm update forces it.

Add a macro

  1. Add an entry to the class list. The list's order is the order macros are created in.
  2. /reload, then /mm resync on each character that should get it (resync creates what's missing and leaves everything else on your bars).

Remove a macro

  1. Delete its entry from the list.
  2. /reload. The addon no longer manages it, so the macro stays on characters that have it. Delete it in the macro window. (/mm clear only removes names that are still in a collection, so it won't find it.)

Rename a macro

Renaming (name) is a remove plus an add: /mm resync creates the new name, and the old macro is left behind for you to delete in the macro window.

Add a class to a collection

  1. Create Collections/<Owner>/<Class>.lua (copy another class file and replace its list, or start from the example above).

  2. Add it to mikey-macros.toc:

    Collections\Mikey\Mage.lua

  3. Restart the game, then /mm list and /mm sync on a character of that class.

Starting a new collection

The quickest way is to copy an existing class file and make it yours. Example: Ulako starting from Mikey's druid.

  1. Copy Collections/Mikey/Druid.lua to Collections/Ulako/Druid.lua.

  2. Change the owner on its ns.Collection(...) line:

    ns.Collection("Ulako").DRUID = {

  3. Add the file to mikey-macros.toc:

    Collections\Ulako\Druid.lua

  4. Restart the game. On your druid: /mm use ulako, then /mm resync.

  5. From now on, edit Collections/Ulako/Druid.lua. Nobody else's changes touch it.

Rename the copied macros while you're at it (see name collisions): Ulako's starter shaman prefixes every name with U_ (U_LB, U_Shock, ...). Names are at most 16 characters.

Switching collections

  • /mm use <name> switches the current character; /mm use default goes back to the default rules. Then /mm resync creates the new collection's macros.
  • Switching never deletes anything. The previous collection's macros stay on the character (and your bars) but are no longer managed.

  • For a clean switch:

    /mm clear
/mm use ulako
/mm resync

    /mm clear removes macros from every collection for the class, so the previous collection's macros go too.

Clearing macros and name collisions

/mm clear deletes this character's macros by name: any character macro whose name appears in any collection's list for the character's class.

  • Shaman example: everything named like Mikey's (LB, Shock, Earth, ...) and Ulako's (U_LB, U_Shock, ...) is deleted; a macro called test is kept.
  • General (account) macros are never touched.
  • There's no confirmation, and deleted macros come off your action bars.

Collisions. Because macros are matched by name:

  • a macro you made by hand with the same name as any collection macro for the class is deleted by /mm clear (and adopted by /mm sync//mm update if it matches the collection you follow);
  • two collections using the same name for different macros can't be told apart: switching between them rewrites the macro in place.

Keep hand-made character macros on names no collection uses, and give each collection its own names (a prefix is the easy way).

Sharing collections

  • A collection is just its folder, so sharing is copying the folder (plus the .toc lines) or a pull request to the repo.
  • Only add collections from people you trust. A collection file is Lua code and runs in the game like any addon, so read one from a stranger before installing it.
  • Updating someone else's collection (a newer copy from its owner, or a git pull) can't conflict with yours as long as you only edit your own folder.

Tips

  • Customize by starting your own collection, not by editing someone else's: your changes stay yours, and theirs can be updated freely.
  • Keep each class list within the character macro limit (30 on Classic Era and retail; see How it works).
  • Use Writing macros for the format, the trimming rules and the shared conventions (mouseover, /startattack, modifiers).
