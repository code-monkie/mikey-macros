Writing macros

The format of a collection's class list, how macros are trimmed to the spells a character knows, and the conventions the existing lists follow.

For where these files live and how they're chosen, see the Collections guide.

A macro entry

{ name = "Kick", spells = { "Kick" }, body = [[
    #showtooltip
    /use [@mouseover,harm,nodead,nostealth] [nostealth] Kick
]] },
  • name: at most 16 characters, unique within the class list (and ideally across collections; see name collisions).
  • spells: every spell the body uses that a character has to learn. These are the names trimmed out until known. Anything not listed (items, other commands) is left alone.
  • learn (optional): the spell, or list of spells, that makes the macro when learned. Without it, learning any spell in spells makes it. Use it when a macro names several spells but belongs to one of them, such as a finishers key: learn = "Eviscerate" with Rupture and Expose Armor on modifiers makes one macro at level 1 instead of one per spell. Spells a macro you have names (but isn't made for) get no generated macro of their own.
  • body: the full macro, written as you'd type it at max level. Indentation and leading/trailing blank lines are stripped. At most 255 characters.

Write the body for a character that knows everything; the addon removes what a lower-level character doesn't know yet.

Combined macros

One key can cover several spells. List them all in spells; each clause is trimmed on its own:

{ name = "Bleed", spells = { "Garrote", "Rupture" }, body = [[
    #showtooltip
    /use [stealth] Garrote; Rupture
    /startattack [nostealth]
]] },

With modifiers, a clause for an unlearned spell falls through to the next one: Ctrl+Imbue gives Rockbiter until Frostbrand is learned.

Trimming rules

  • /use, /cast and /castsequence lines are trimmed. A line is split into clauses at ;; a clause's spell is the text after its last ], ignoring a leading !. If that spell is in spells and not known, the clause is dropped; if no clause is left, the line is dropped.
  • In a /castsequence, unknown spells drop out of the sequence.
  • #showtooltip is trimmed the same way, clause by clause: #showtooltip [mod:shift] Rupture; Eviscerate before Rupture is learned is #showtooltip Eviscerate. With nothing left it becomes a bare #showtooltip.
  • Spells are matched by name, so ranks don't matter. A deliberate low-rank copy such as Earth Shock(Rank 1) (a cheap interrupt) counts as Earth Shock: list "Earth Shock" in spells.
  • Every other line (/startattack, /dismount, /target, /pet...) stays.

A macro with nothing known yet keeps only its other lines and shows a question mark. Once a spell is learned, its clause comes back and #showtooltip shows the live icon.

Built bodies

A body can also be a function returning the macro text, called with a context table:

  • c.knows("Spell Name"): whether the spell is known.
  • c.dagger: whether a dagger is in the main hand.
{ name = "Example", spells = { "Backstab", "Sinister Strike" }, body = function(c)
    local strike = c.dagger and "Backstab" or "Sinister Strike"
    return "#showtooltip\n/use " .. strike
end },

The result is trimmed like any other body. Prefer plain text; use a function only when the text depends on more than which spells are known.

Conventions

The existing lists follow these, which keeps classes consistent:

  • #showtooltip on every macro; the macro's own icon is the question mark, so the live spell icon shows.
  • /use, never /cast (the same for spells, and /use also takes items and equipment slots). /castsequence is the exception; it has no /use form.
  • No spell ranks, except a deliberate low-rank copy (Spell(Rank 1)).
  • Mouseover with fallback for things you aim: [@mouseover,harm,nodead] [] for harmful spells, [@mouseover,help,nodead] [] for friendly ones, and [@player] as the fallback for self-buffs and cures.
  • No mouseover on melee abilities you spam; they act on your target.
  • /startattack on damage, /startattack [nostealth] on stealth openers, /stopattack and/or /stopcasting around crowd control.
  • ! on toggles (!Stealth, !Ghost Wolf) so a second press doesn't cancel.
  • Modifiers mean the same thing across a class: Shift = fire, Ctrl = frost, Alt = a fourth option (shaman shocks, imbues and totems; hunter traps).
  • Druid: only Bear is reliably [form:1]; other form numbers depend on the order forms are learned, so use other conditions ([swimming] for Aquatic).
  • Hunter: attacks carry the pet rider (/petattack [pet], /petdefensive [pet,group], /petassist [pet,nogroup]).

Limits

  • At most 16 characters per name and 255 per body. /mm sync skips and reports a body that's too long.
  • Keep a class list within the character macro limit (30 on Classic Era and retail).

Checking your macros

The VS Code extension checks collection files as you type: bad conditions and units, brackets, missing ;, name and length limits, spells missing from spells, files missing from the .toc and names shared between collections. It also colors macros and autocompletes conditions, units, commands and spells. It can't tell whether a spell name exists in the game.
