VS Code extension

mikey-macros lint helps you write collection files in VS Code. It works on the macro text inside body = [[ ... ]] and leaves the Lua around it alone: it checks macros as you type, colors them, autocompletes conditions, units, commands and spells, and explains macro syntax when you hover.

It's built from tools/vscode-mikey-macros/ in this repository and installed from a local file; it isn't on the VS Code Marketplace.

What it does

It switches on for any Lua file containing an ns.Collection("Owner").CLASS = { ... } line, so every file under Collections/, and nothing else.

FeatureIn short
ProblemsSquiggles and Problems-panel entries for mistakes in macros, the .toc, and names shared between collections.
AutocompleteConditions, units, condition values, slash commands, # lines and the macro's own spells.
HoverWhat a condition, unit, command or #showtooltip means.
ColorsCommands, conditions, units, values and separators each in their own color, in any theme.

Installing

You need VS Code and Python 3 (only to build the package; no Node or npm).

  1. Build the package. In a terminal, from the mikey-macros folder:

    python tools/vscode-mikey-macros/build_vsix.py

    It writes mikey-macros-lint-<version>.vsix next to the script. (Built files aren't committed; .gitignore skips *.vsix.)

  2. Install it. In VS Code open the Extensions view (Ctrl+Shift+X), click the ⋯ menu at the top of the view, choose Install from VSIX… and pick the .vsix. Or from a terminal:

    code --install-extension tools/vscode-mikey-macros/mikey-macros-lint-0.3.0.vsix

  3. Open the addon folder (File → Open Folder → mikey-macros) and open any collection file, e.g. Collections/Mikey/Druid.lua. Commands such as /use turn purple and conditions teal, which means it's working.

Opening the whole mikey-macros folder, rather than a single file, lets the extension find mikey-macros.toc and the other collections for the checks that span files.

Using it

Problems

Problems appear as you type: squiggles on the exact text, and entries in the Problems panel (Ctrl+Shift+M). Hover a squiggle for the message.

Errors, which stop a macro working or the game loading a file:

  • a name over 16 characters, a body over 255, or two macros with the same name in a class;
  • an unbalanced or nested [ ];
  • an unknown condition or unit (nocomba, @mosueover);
  • conditions after a spell name, meaning a missing ; ([stealth] Ambush [nostealth] Backstab);
  • #showtooltip with no space before the spell (#showtooltipMangle), or an unknown # line (#howtooltip);
  • a collection file that isn't listed in mikey-macros.toc; the message gives the exact line to add;
  • a .toc line that points at a missing file, shown on the .toc itself.

Warnings, worth a look:

  • a spell on a /use line that isn't in spells, so it's never trimmed (fine for items, or spells every character of the class knows from level 1);
  • a spell in spells that the body never uses;
  • an unknown slash command (/startattac);
  • the same macro name in another collection for the class; /mm clear and switching collections treat them as one macro (see name collisions).

Problems in other files (the .toc, shared names) refresh whenever you save.

Autocomplete

Suggestions appear inside macro bodies only, each with a short description. Press Ctrl+Space to bring them up anywhere in a macro.

Where you areSuggestions
after [ or ,conditions (combat, stealth, harm, ...), their no versions, and @units
after @units: @mouseover, @player, @target, @focus, @pet, @cursor, ...
after mod:, form:, equipped:, group:, button:, spec:their values (shift / ctrl / alt, form numbers, weapon types, ...)

# at the start of a line#showtooltip, #show
where a spell goes on a /use or /castsequence linethe spells in this macro's own spells list, so names match exactly

Hover

Hover over a condition (nocombat, mod:shift, form:1), a unit (@mouseover, @focustarget), a slash command, reset= or #showtooltip to see what it means. Unknown conditions and units are flagged in the hover too.

Colors

The extension brings its own colors for macro text, so they look the same in any theme:

Changing a color: add a rule for its scope to your settings. For example, orange conditions:

"editor.tokenColorCustomizations": {
    "textMateRules": [
        { "scope": "support.type.condition.wow-macro", "settings": { "foreground": "#FF8800" } }
    ]
}

A editor.tokenColorCustomizations setting of your own replaces the extension's defaults as a whole, so if you already have one, copy all the rules you want into it (see Troubleshooting).

Updating and removing

  • Updating: after the extension changes (a git pull, or your own edits in tools/vscode-mikey-macros/extension/), bump version in its package.json, rebuild with build_vsix.py, and install the new .vsix over the old one. Reload the window if VS Code asks.
  • Removing: Extensions view → mikey-macros lint → Uninstall.

The extension is plain JavaScript (extension/extension.js) plus a coloring grammar (extension/syntaxes/wow-macro.injection.json); the reference lists of conditions, units and commands are near the top of extension.js.

Troubleshooting

  • Nothing happens in a collection file. Check the language in the status bar says Lua, and that the file has its ns.Collection("Owner").CLASS = { line. Check the extension is enabled in the Extensions view.
  • No .toc or shared-name problems. Open the mikey-macros folder itself, not just a file, so the extension can find mikey-macros.toc.
  • Macro text is all one color. Your settings probably have their own editor.tokenColorCustomizations, which replaces the extension's colors. Add the rules from Colors to it, one per scope, with the colors above.
  • A word looks the wrong color. Put the cursor on it and run "Developer: Inspect Editor Tokens and Scopes" from the command palette (Ctrl+Shift+P) to see which scope it got.
  • python isn't found when building. Install Python 3 for Windows (tick "Add to PATH"), or run the script with py or python3.

Limits

  • Spell names aren't checked against the game, so a misspelled spell shows up as a macro that never fills in.
  • Macros whose body is a function (built bodies) aren't checked or colored.
  • Condition, unit and command lists cover Classic and retail macros; a brand-new condition would show as unknown until the list is updated.
